FitLah Cloud Implementation Guide
Version 0.1.8

This guide explains how to implement FitLah on Vercel with Neon PostgreSQL.
It intentionally describes the cloud deployment path only.

1. Prepare the repository

Push the project to GitHub.

Do not commit:
- .env
- virtual environments
- API keys
- database dumps
- user uploads

2. Create the Neon database

Go to:

   https://neon.tech

Create a new project.

In the Neon dashboard:
- Open Connect.
- Select the app database and role.
- Enable connection pooling.
- Copy the pooled connection string.

The value should look like:

   postgresql://USER:PASSWORD@HOST-pooler.REGION.aws.neon.tech/DB?sslmode=require&channel_binding=require

3. Create the Vercel project

Go to:

   https://vercel.com

Import the GitHub repository.

Use these settings:
- Framework Preset: Other
- Build Command: blank/default
- Output Directory: blank/default
- Install Command: blank/default, or pip install -r requirements.txt

FitLah deploys through:

   api/index.py

Do not configure a Start Command.

4. Add Vercel environment variables

Open:

   Vercel Project -> Settings -> Environment Variables

Add these variables for Production:

   DATABASE_URL=your Neon pooled connection string
   FITLAH_SECRET_KEY=replace-with-a-long-random-secret
   FITLAH_PRODUCTION=true
   FITLAH_COOKIE_SECURE=true
   FITLAH_DB_DISABLE_POOL=true
   FITLAH_PUBLIC_BASE_URL=https://fitlah.vercel.app
   FITLAH_ALLOWED_ORIGINS=https://fitlah.vercel.app
   FITLAH_ALLOW_STRAVA_SETTINGS_WRITE=false
   GEMINI_API_KEY=
   GEMINI_MODEL=gemini-3.1-flash-lite

Optional:

   FIELD_ENCRYPTION_KEY=your-fernet-key

If FIELD_ENCRYPTION_KEY is omitted, FitLah derives encryption from
FITLAH_SECRET_KEY.

5. Deploy to Production

Go to:

   Vercel Project -> Deployments

Redeploy the latest GitHub deployment as Production.

Environment variable changes do not affect an already-running deployment until
you redeploy.

6. Attach the domain

Open:

   Vercel Project -> Settings -> Domains

Confirm the project domain:

   fitlah.vercel.app

If you use another custom domain, add it here and then update:

   FITLAH_PUBLIC_BASE_URL=https://your-domain.com
   FITLAH_ALLOWED_ORIGINS=https://your-domain.com

Redeploy after changing those values.

7. Verify the deployment

Open these URLs:

   https://fitlah.vercel.app/healthz
   https://fitlah.vercel.app/healthz/db

Expected /healthz response:

   {"database":"configured","missing_recommended":[],"missing_required":[],"success":true}

Expected /healthz/db response:

   {"database":"ok","success":true}

8. Configure Strava

Go to:

   https://www.strava.com/settings/api

Use:

   Website: https://fitlah.vercel.app
   Authorization Callback Domain: fitlah.vercel.app

Important:
- Strava wants only the domain in Authorization Callback Domain.
- Do not enter https://.
- Do not enter /strava-sync.
- Do not enter a trailing slash.

In FitLah, open:

   Settings -> Strava ID / Client secret

Save the Strava Client ID and Client Secret.

9. Confirm app data saves to Neon

Create a new FitLah account from the deployed site.

Then check Neon:
- Open Tables in the Neon dashboard.
- Confirm a new row exists in users.
- Confirm app-created tables such as personal_bests and activity_records exist.

10. Troubleshooting

If /healthz says DATABASE_URL is missing:
- Add DATABASE_URL under Vercel Production environment variables.
- Redeploy Production.

If /healthz/db says connection_failed:
- Use the Neon pooled connection string.
- Confirm sslmode=require is present.
- Confirm the Neon project is active.

If signup succeeds but Strava redirects fail:
- Confirm FITLAH_PUBLIC_BASE_URL matches the final deployed domain.
- Confirm Strava Authorization Callback Domain is the domain only.

If uploaded webcam videos disappear:
- This is expected on Vercel serverless functions.
- Use object storage such as Vercel Blob or S3 for durable uploaded videos.
